# 개발용 69항목 판정 근거 재집계 (2026-11-16, 출력 잘림 처리 고친 판)

이 폴더에는 `dataset_pilot/dev_judgment_recount.py`의 결과가 들어 있습니다.
- 저장된 실행 기록(runner 출력)을 `judge.py`로 다시 판정해, "취약"이 어떤 시험 결과에서 나왔는지 나눠 셌습니다.
- 모델 호출과 프로그램 실행은 하지 않았습니다.
- 출력은 개수와 D 번호(D01~D69)뿐입니다.

- `판정근거_재집계.md`: 표 세 개.
- `판정근거_항목별.csv`: 기능을 통과한 취약판 번역 64개 각각의 분류.

**고친 점(같은 날 첫 판 대비).** 첫 판은 출력이 잘린 시험을 "기대값이 짧으니 긴 출력은 오답"이라고 보고 정상 출력으로 셌습니다. 이 근거는 부족합니다. 공백이 많이 든 JSON처럼, 올바른 값이 4,000자를 넘을 수 있기 때문입니다. 그래서 이번 판은 이것을 **"출력 잘림만(세부 판정 불가)"**으로 따로 두고, 비교 ㉠·㉡에서는 뚫림으로 세지 않았습니다. 현재 규칙의 숫자(기록 그대로)는 바뀌지 않습니다.

## 확인한 것
1. **현재 규칙으로 다시 세도 숫자는 같습니다.**
   - 다시 판정한 결과가 저장된 번역 판정과 69항목 모두 같았습니다.
   - 조건별 숫자도 같습니다: 54, 명세 자기 수정 11, 두 번 11, 자기 비판 반복 38, 기준 없이 26, B6 11, 정책 제공 7.
   - 분류 규칙은 가짜 기록 11개로 먼저 확인했습니다.
2. **패닉·진짜 충돌·시간 초과는 0건입니다.**
   - 개발용 기록에는 Rust 패닉 0, 진짜 충돌 0, 시간 초과 0(무효 0)입니다.
   - "Rust 패닉은 뚫림" 규칙과 시간 초과 처리 규칙은 이 숫자에 영향을 주지 않았습니다.
   - 다만 모델 한 개, 69항목의 기록이므로 본 실험 규칙이 맞다는 근거는 아닙니다.
3. **출력 잘림 때문에 세부 판정을 할 수 없는 번역이 3개 있습니다.**
   - 무슨 일이 있었나: `runner.py`는 stdout의 마지막 4,000자만 남깁니다(`_exec`). 그래서 4,000자가 넘는 한 줄은 앞이 잘려 JSON이 깨지고, `judge.py`는 이를 충돌(crash, 뚫림)로 셉니다.
   - 해당 번역: D05(CWE-770), D24·D31(CWE-1333). 세 항목 모두 보안 시험이 1개뿐이라, 취약 여부 자체가 이 잘린 출력에 달려 있습니다. 원래 Python도 같은 시험에서 똑같이 잘렸습니다.
   - 54개를 나누면: 51개는 잘림 없이 뚫린 것이 확인되고, 3개는 세부 판정 불가입니다.
   - 조건별로 판정 불가가 든 번역 수:

     | 조건 | 여전히 취약 | 그중 판정 불가 |
     | --- | --- | --- |
     | 명세 자기 수정 | 11 | 2 |
     | 두 번 | 11 | 2 |
     | 자기 비판 반복(기준 거침) | 38 | 3 |
     | 자기 비판 반복(기준 없이) | 26 | 2 |
     | B6 | 11 | 3 |
     | 정책 제공 | 7 | 2 |

   - 54·11·7이 틀렸다는 뜻은 아닙니다. 다만 이 재집계만으로 그 판정이 맞다고 확인할 수는 없습니다.
   - 확인하려면 잘리지 않은 출력이 필요합니다. 저장된 프로그램 6개(번역 3개와 원래 Python 3개)를 격리 컨테이너에서 출력 한도 없이 다시 돌리거나, 번역 코드를 직접 읽어야 합니다. 이번에는 하지 않았습니다.
   - 실행기 보완: 한도만 늘리기보다, 판정에 쓰는 출력(전부 또는 해시와 길이)과 화면에 보여 줄 짧은 로그를 따로 저장해야 합니다.
4. **'값 대신 오류'가 숫자의 상당 부분을 만듭니다.**
   - 값을 기대한 보안 시험에서 오류를 내면, 데이터셋 판정은 뚫림으로 셉니다. 다섯 칸 분류는 같은 결과를 '다른 형태로 거부'로 셉니다.
   - 이것만으로 취약인 번역: 명세 자기 수정 11 중 1, 자기 비판 반복 38 중 8, 기준 없이 26 중 18, B6 11 중 1, 정책 제공 7 중 1.
   - 수정판에서 새로 생긴 취약도 대부분 이것입니다. 자기 비판 반복은 2개 모두, 기준 없이는 8개 중 6개, B6은 1개 모두입니다.
   - 받아들임·값 다름으로 뚫린 것만 세면(비교 ㉡, 출발 51개 기준): 명세 자기 수정 8, 자기 비판 반복 27, 기준 없이 6, 정책 제공 4.
5. **효과 시험은 이 69항목에서 돌린 적이 없습니다.**
   - 효과 시험 파일: 94는 4항목 중 0개, 95는 5항목 중 0개, 502는 4항목 중 4개입니다.
   - 54·11·7은 데이터셋 판정의 수이고, 공격 효과가 실제로 일어난 번역 수가 아닙니다.
6. **다른 종류 오류로 막음(format_error).**
   - 번역 직후 5개 번역(시험 9개)이 기대와 다른 종류의 오류로 막음 처리됐습니다.
   - 자기 비판 반복 뒤에는 13개 번역(27개), 기준 없이는 16개(39개)입니다.

## 이 집계로 볼 수 없는 것
- Python→Python 대조는 이 69항목에서 돌리지 않았습니다. 그래서 Python 쪽 예외 처리의 비대칭이 실제로 몇 건을 만드는지는 셀 수 없습니다.
- 두 비교(㉠ 비정상 종료와 출력 잘림을 뺌, ㉡ 받아들임·값 다름만 셈)는 규칙 제안이 아닙니다. 어느 하위 종류가 숫자를 만들었는지 보려는 집계입니다.
- `00_정리본.md` 사례 2의 D05는 3번 때문에 근거로 쓰지 않도록 정정했습니다. "명세를 다시 읽혀도 남음"은 D20(잘림 없음)으로 말할 수 있습니다.
