# 개발용 Haiku 69항목: 판정 근거 재집계

만든 방법: `dataset_pilot/dev_judgment_recount.py`. 저장된 실행 기록을 `judge.py`로 다시 판정했다. 모델 호출 0, 프로그램 실행 0. 분류 규칙은 가짜 기록 11개로 먼저 확인했다. 다시 판정한 결과는 저장된 번역 판정과 69항목 모두 같았다.

숫자는 모두 번역 수(괄호 안은 보안 시험 수)다. '비교용 집계'는 비정상 종료(패닉·충돌·인정된 시간 초과)로만 뚫린 시험을 뚫림에서 뺀 값이다. 규칙을 바꾸자는 것이 아니라, 지금 숫자에 비정상 종료만으로 잡힌 것이 얼마나 섞였는지 보려는 것이다.

## 1. 처음 취약했던 번역이 무엇으로 '취약'이 됐나 (취약판 출발)

각 조건의 최종 프로그램에서, 원래 Python에서도 뚫렸고 최종 프로그램에서도 뚫린 보안 시험의 하위 종류로 번역을 나눴다. '정상 출력'은 입력을 받아들였거나(accepted) 값이 달랐던(wrong_value) 것, '비정상 종료'는 패닉·충돌·인정된 시간 초과, '출력 잘림'은 정상 종료했지만 한 줄이 4,000자를 넘어 실행기가 앞을 잘라 judge.py 가 crash 로 센 것이다. 잘리기 전 출력이 기대값이었는지 알 수 없으므로 세부 판정 불가로 따로 두었다(현재 규칙의 뚫림 판정은 기록 그대로 센다; 비교 ㉠·㉡에서는 빼고 셌다). '값 대신 오류'는 값을 기대한 시험에서 오류를 낸 것이다(데이터셋 판정은 뚫림으로 세고, 다섯 칸 분류는 '다른 형태로 거부'로 센다). 분류 칸은 그 조건 뒤에도 취약한 번역을 나눈 것이라 합이 '여전히 취약'과 같다.
